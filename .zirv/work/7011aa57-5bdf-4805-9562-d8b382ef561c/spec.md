# Specification

## Context

This is one PR for #737–#741 on top of `origin/main` at `4e2f9874` (Cargo version `4.20.0`). Issue #537 already supplied the shared `ctx::jev` client and cache, operator-only `[jev]` gates, proxy intake, memory reranking, `run_loop::jev_judge_continue`, `task::respawn_decision_with_jev`, and `workflow::review::advise_duplicates`. This PR must turn advice into demonstrable omitted prompt bytes or avoided launches, and distinguish that evidence from an answer or an illustrative savings estimate.

`prompt::skill_index_text` puts every implicit skill ID and its first-sentence description in the stable prefix. `compile.rs` and native `runtime/context.rs` share that text. Full skill instructions and reference bodies are already loaded on demand; they are not a current inline token cost. `agent::attach_task_context_to_prompt` appends capped parent task outcomes before a delegated worker launches. `workflow::team::compile` is pure and the shared `compile_for_objective`/CLI plan paths store its result. The proxy already asks whether clarification is needed and `chat::maybe_clarify` performs one interactive follow-up. Review convergence currently follows `new_finding_count == 0` after a completed round, while a repeat `review run` still enters the reviewer launch path. The supervisor already bypasses the helper on a decisive Jev `continue`, and crash triage can block a deterministic retry early.

The TypeSafe connection, timeout, decision cache, answer/fallback JSONL and spend row remain in `ctx::jev`; no new service or dependency is needed. `runtime::native_available() == cfg!(test)` remains unchanged.

## Goals

- Select optional skill descriptions and prior parent-report details before supported Claude/Codex launches. Keep every implicit skill ID visible, all explicitly invoked descriptions, canonical/required instructions, task constraints, provenance, mandatory evidence, and on-demand `zirv skill list/load` and `zirv ctx task show` routes.
- Use the existing proxy and team planner to ask a material clarification before an expensive launch and, when safe, omit one redundant optional planning seat. Keep the compiled team policy and required reviewers authoritative.
- Prove actual helper suppression, review reuse, and futile retry prevention with bounded outcome evidence; keep completion and recovery observable so false savings can be detected.
- Preserve byte/order/behavior parity, and perform no Jev request, cached-answer read, decision/spend/effect write, when a relevant gate is off or the configured credential is empty/missing.

## Non-goals

- Issues #742 onward and other recommendations in the source analysis; a general orchestration rewrite, new retry policy, new permission grant, or automatic completion approval.
- Claiming savings for descriptions or reference bodies that baseline never injected, for an advisory answer without an actual effect, or for a hypothetical future worker/review launch.
- Changing `rot.rs`, the native runtime availability gate, built-in policy floors, required independent review counts, or the default operator configuration on this computer.

## Design

### Activation and shared recording

Add operator-only, default-false `jev.context`, `jev.intake_savings`, and `jev.review_reuse` with matching `ZIRV_CTX_JEV_CONTEXT`, `ZIRV_CTX_JEV_INTAKE_SAVINGS`, and `ZIRV_CTX_JEV_REVIEW_REUSE` mappings and `REPO_FORBIDDEN` tests. Existing `jev.supervisor` controls #739/#741; existing `jev.review` still controls the first dedup decision, while `review_reuse` separately controls skipping a later reviewer launch. Every effect is guarded by both its gate and `jev::available(&cfg.proxy.typesafe)` **before** cache access or any file write. The existing `proxy.typesafe` endpoint/model/credential/timeout, decision cache TTL, no-retry HTTP request, decision JSONL, and TypeSafe spend row remain the connection contract. `jev::advise_detailed` returns `Disabled | MissingCredential | Answered(Answers) | Failed`; the existing `advise` delegates to it and keeps its `Option<Answers>` behavior. A partial or non-decisive answer is handled by the site as deterministic fallback. Disabled/missing-key state is visible through existing `jev status`, with no off-path event I/O.

Add one private, append-only `jev-effects.jsonl` for *observed actions*. `jev::record_effect(cfg, state, gate, &JevEffect)` itself checks gate and credential. The typed row carries `site`, static `action` and optional static `reason`/`outcome`, timestamp, session/principal from existing Jev identity, optional bounded `subject_id` (task/workflow/objective fingerprint) and `item_id` (seat/finding/cycle), optional `baseline_count`, `actual_count`, `removed_bytes`, `elapsed_ms`, and optional observed usage split into fresh input, cache creation, cache read, and output tokens. Unknown usage fields are absent, never zeroed or added to a savings total. No raw request, finding, crash reason, report, path content, or Jev explanation enters an effect row. A planned seat omission is labeled a *plan* effect; only a launch site may report a process actually skipped. Existing provider/delegation/workflow logs supply the joinable task result, launch count, and known token usage; no duplicate general telemetry framework is added.

### #737: task-specific optional context

At task-aware launch seams, build a deterministic bounded candidate list from the skill registry's implicit descriptions and, for `zirv agent --task`, the already-loaded parent card outcomes. The operator task/brief is bounded and passed through the existing secret-protection helper before Jev sees it; if obfuscation is off or protection fails, keep the baseline without asking Jev. Candidate state contains IDs, trust/source labels, lengths, and short protected descriptions or titles; never full skill/reference files, parent outcome bodies, diffs, or secrets. Required canonical instructions, user/system prompt layers, card brief, dependency identity and status, explicit invocations, and required evidence are not candidates. A single batched Noul call asks relevance for shortlisted optional descriptions/details. A decisive low-relevance answer may omit that description/detail; relevant, missing, partial, uncertain, out-of-cap and error cases retain baseline material in original order. The relevance floor is conservative and documented beside the code; no model-authored content may cause material to be added or an instruction removed.

Keep an ID-only skill discovery index in the stable prefix on the active path. Render the selected optional descriptions after the canonical stable layers and before task-specific memory/mail material, so different tasks do not mutate the stable prefix. Keep explicitly invoked skill descriptions even when Jev says irrelevant. The original index rendering is unchanged off-path. The wrapped compiler and native context compiler share the selected-index renderer; the native path remains available only under its current test gate. Selection occurs before the initial supported `chat`/`exec`/`agent` launch. Wrapped sessions that recompile via `hook` read a private session-scoped selected-ID set only after the gate and credential check; the record is keyed by task hash and source fingerprint, invalidates on a changed task or registry/card source, and cannot silently apply to another session. If no task or no valid selection is available, compile exactly as before. The parent outcome splice is at `agent::attach_task_context_to_prompt` (no `task.rs` edit): preserve a terse ID/title/status plus `zirv ctx task show <id>` pointer for an omitted optional body. Count bytes from the actual rendered before/after prompt, with cache effect separated; do not count on-demand reference bodies as removed bytes.

### #738: intake clarification and one optional seat

The existing proxy TypeSafe request remains the single intake call. When `jev.intake_savings` is active, batch a bounded ambiguity-category choice with its current `needs_clarification` question. Only a decisive material-ambiguity result invokes the existing one-round `chat::maybe_clarify` path; the category selects a fixed, prewritten question, not generated free-form text. A missing category or weak answer uses today's generic prompt or deterministic baseline. Record requested versus nonempty answered clarification, and the subsequent launch/completion via existing session logs. Do not extend interactive questioning beyond one round or block on noninteractive input.

Keep `workflow::team::compile` pure. After it returns, the shared planning entry point and CLI `team plan` may ask Jev one bounded question about **implicit `planner-1` only** when the optional planner has no distinct outstanding deliverable (for example an accepted current plan already covers the breakdown). Explicit `--seat`, a required reviewer/security/tester, writer, debugger, architect, or domain specialist is never removable. Omit `planner-1` only on a decisive answer and after validating the remaining plan's dependencies, groups and limits; any failure keeps the original plan. Store/return the final plan that later `team brief` actually reads. Record baseline/final plan seats as a plan effect; only an actual admission/launch guard can report a launch avoided. Preserve explicit delegation and useful parallel work. There is no second execution-profile classifier and no lowering of sensitive-task or review floors.

### #739: supervisor judge

Reuse `jev_judge_continue` after deterministic gate and no-progress decisions. Record accepted continue and the helper call actually skipped; classify answered-but-uncertain/non-continue and error fallbacks separately from helper invocation. The Jev answer never declares done, blocked, or wait. After two consecutive accepted Jev continuations, force the baseline helper judge on the next eligible cycle; reset the streak when the helper runs. Preserve the existing no-progress cycle limit. Join effect rows with the objective's cycle/outcome and existing helper/delegation usage; report helper input/cache/output tokens only if observed. Tests must prove the helper closure/process was suppressed, the forced recheck prevents a false-continue loop, and every other result reaches the baseline helper path.

### #740: review dedup and reuse

Retain `advise_duplicates` as Minor/Note-only annotation and `new_finding_count` as the completed-round convergence rule. Add durable `jev_dedup_converged` evidence only when a completed, recorded review has a genuinely semantic duplicate that baseline exact-key matching would have counted as new, no new findings, no unresolved Major/Critical or other blocker, and required independent review evidence is satisfied. With `jev.review_reuse` active and credential present, a later `workflow review run` may return the stored converged result before launching a reviewer only if the current change fingerprint, resolved reviewer harness/model identity, completed evidence, required reviewer count, and blocker state still match. If model identity cannot be resolved, run the reviewer. `--fresh` forces a new reviewer launch. A changed diff, different reviewer identity, partial/error answer, unresolved blocker, or unmet required review always follows the existing launch path. Record the semantic dedup, convergence reason, completed launch, and any *actual* later skipped launch separately.

### #741: crash retry

Keep `respawn_decision` first and authoritative. `respawn_decision_with_jev` may narrow a baseline-eligible retry to `AutoBlock` only for a decisive repeatable access/configuration or deterministic cause; transient or incomplete reports, uncertain/partial/error answers, and any refusal follow baseline. Preserve attempt ceilings and the existing blocked-card recovery/resume path. Give the operator a bounded reason and the existing task command needed to inspect/resume. Record baseline eligibility and only count an avoided launch when a retry would actually have been admitted; correlate subsequent unblocking/recovery and terminal task status so a stopped failed worker is never counted as a completed task or automatic token saving.

### Ownership and integration

Context/integration owner: `ctx/config.rs`, `ctx/jev.rs`, `ctx/compile.rs`, `ctx/prompt.rs`, native `runtime/context.rs`, launch selection wiring outside `agent.rs`, README and Cargo manifest/lockfile. Intake owner: `ctx/proxy/`, `ctx/chat.rs`, `workflow/team.rs` and its shared planner call; no config/README/manifest edits. Reliability owner: `ctx/run_loop.rs`, `ctx/task.rs`, `ctx/agent.rs` (both crash effects and the parent-report caller splice), `workflow/review.rs`, its review evidence fields in `workflow/engine.rs`, and focused tests. The context owner exposes `compile::task_context_with_selected_reports(cfg, state, card, parents, cap)` to replace the current `task::compile_task_prompt` call in `agent.rs`; it returns precisely that baseline output when inactive or fallback. Root owns git integration and PR. Each owner uses the shared effect/status API above, avoids overlapping files, and reports only changed paths plus fresh evidence.

## Testing strategy

Write a failing inline regression for each changed behavior, then use local one-shot HTTP fixtures for enabled answers, partial/uncertain answers, 5xx and timeout. Isolate operator config, credential env, and state per test; a warm Jev cache must not be read on a disabled/missing-key path. Compare rendered bytes/order and output for gate-off versus main behavior, including a task-aware launch with no key. Cover relevant/irrelevant/mandatory/explicit skills, source/task fingerprint invalidation, parent report fallback and on-demand access, and both supported harness prompt routes. Cover direct, ambiguous, substantial and sensitive intake, explicit seats and required reviewers; assert actual final plan/launch effects. For judge, assert helper call count and false-continue bounded termination; for review, assert same issue with changed wording/line, different issue with similar wording, multiple reviewers, blockers, fingerprint changes, `--fresh`, and actual no-launch; for crash, assert transient/incomplete versus repeatable failures, refusal ceilings, recovery and final status. Test the effect log only for events actually taken and verify unknown usage stays absent. Use matched task runs, fixed model/effort/review policy, and separately report fresh input, cache creation, cache reads, output, latency, completion and rework where observed; never infer token savings from a fixture alone.

After focused tests pass, run once to completion in the worktree: `cargo build`, `cargo nextest run --no-fail-fast`, `cargo fmt -- --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test -- --test-threads=1`. Report command exit codes and any failing test names/errors verbatim. Update README's `[jev]` configuration, environment mapping and trust-boundary explanation, and bump `Cargo.toml` above `4.20.0` because `src/` changes.

## Risks

- A task-specific description in the stable prefix would churn provider caches. Keeping the active-path ID index stable and selected descriptions late avoids this; baseline composition is untouched when inactive.
- Pruning an instruction or required parent result could derail a task. Eligibility is limited to optional descriptions/details, with ID/status and on-demand retrieval retained; uncertain and missing answers preserve the candidate.
- A warm answer cache could bypass a missing credential. Every site, effect write and session selection read checks gate plus nonempty key before cache access.
- A duplicate nit could hide a new blocker or waive a review. Reuse requires completed matching evidence, all required reviewers, no blocker, and an explicit `--fresh` escape; Major/Critical never become semantic duplicates.
- Saved helper calls or blocked retries could add cycles or reduce completion. Record later task outcome/recovery and enforce existing cycle/retry limits; add a bounded recheck only if the false-continue test shows a real gap.
