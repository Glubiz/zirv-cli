zirv dash refresh: wrapped sessions, limits, motion and intake

Proposed changes to the wrapped-session dashboard, its motion, and the prompt proxy that runs before a session starts. The current frame is rebuilt from dash/ui.rs; every proposed value maps to data zirv already has or a small, named addition. Nothing is implemented yet.

01 · DASHBOARDNarrower session column, pane header, limits in the dead space

  • Session column goes from 44 to 28 columns. Rows keep the group tree, state glyph, rot score, and gain a mail or approval badge.
  • The 8-line fact block becomes 2 lines: state with time, and workflow step. Group, model, budget, branch and signal are gone; the model moves to the pane header.
  • A pane header row, like the native pane: harness, role, model, folder, workflow step, and a working indicator.
  • The column's empty lower half shows usage limits with exact reset times.
  • The footer shows the rot track and, on the orchestrator, the distance to rollover. Cost is removed from the footer and the sidebar; zirv ctx status keeps it.
  • "● supervised" and "socket bound" disappear while healthy; only a problem (unsupervised, stalled) is shown.

Under 100 columns the session column hides and sessions become tabs in the header, the way the native pane already behaves. ^A b brings the column back.

02 · ROT AND ROLLOVERHow rotten the session is, and how close the orchestrator is to rolling over

zirv does not compact or restart dashboard sessions; only rollover is automatic. The rot score you already like becomes a track with its colour bands marked: ┊ warming at 40 and ┊ rotting at 60 (your score.advise_at and score.compact_at). From 60 the footer recommends what to do. Rollover is an orchestrator-only segment on the right; the sidebar row carries ⤓ or ⏸ while it is pending or parked.

FreshBelow 40. Nothing to do.
Warming40 to 59, between your score.advise_at and score.compact_at.
Rotting60 and up. zirv does not compact dashboard sessions, so it tells you.
Very rotten80 and up (score.restart_at).
Rollover distanceOrchestrator only. Headroom left against the 20% rollover floor.
Rollover soonWithin 10 points of the floor.
Rollover pendingThe seat is marked pending and swaps when the session is idle. The chip breathes.
ParkedNo fallback had headroom, so the seat waits for the reset.
Rolled overA toast in the pane header for 5 s after the swap.

03 · LIMITSExact reset times for the 5-hour and weekly windows

zirv already stores the vendor's resets_at for both windows (Claude's statusline, Codex's rate-limit events); the dashboard drops it today. Resets today show the clock time and a countdown; later resets show the weekday. A ~ marks zirv's own estimate when no vendor reading exists yet. Only enabled, available harnesses appear: a disabled Codex or Claude gets no block, even with old usage files on disk.

ExactVendor reported the reset time (Claude statusline, Codex rate-limit events).
EstimatedNo vendor reading yet. The time is zirv's estimate, marked with ~.
Close80% and above turns yellow; the countdown is the part to watch.
HitLimit reached: red, with the exact time it comes back.
On creditsCodex served past the limit from paid credits.

03 · JEVWhat Jev did in the last 24 hours

A section between sessions and limits, from the same jev-decisions.jsonl and jev-effects.jsonl that zirv ctx jev status rolls up, narrowed to 24 hours: calls and cache hits, p95 wait, errors, the latest call, and the three busiest gates. Jev records carry no session id, so the numbers are machine-wide. The last line flashes when a new call lands. Spend stays out, like the rest of the dash. With every Jev gate off the section is not shown at all.

OnNormal: gates enabled, key present.
ErrorsErrors in the window turn red with the latest reason.
No keyGates enabled but the credential is missing.

05 · WORKFLOW STEPEach pane shows its own workflow, not the repo's newest

Why it is wrong today: the dashboard reads one "active workflow" pointer per repo and shows it on every pane. Any zirv workflow start in the repo moves that pointer, and a finished run can leave it pointing at a step that no longer exists, which renders as an empty step. The fix records the workflow id a session started on its session record and resolves each pane from that.

RunningThe workflow this session started, with its current step and position.
Needs youAn approval gate is waiting.
FinishedThe run completed. It stays for 10 minutes, then the segment goes.
NoneThis session started no workflow. Nothing is shown; no guessing from the repo.

06 · MOTIONCalmer, clock-driven motion with a few deliberate moments

  • Spinners run on a clock. Today they advance once per redraw, so they speed up to ~100 fps while you type and slow to 20 fps when idle.
  • The working verb in the pane header gets the Claude Code shimmer.
  • Gauges ease to new values over about 300 ms instead of jumping once a second.
  • A pending rollover breathes until it happens. New mail or a finished worker flashes its row once.
  • Toasts appear in the pane header and fade after 5 s.
  • One setting, dash.motion = "full" | "reduced", default full. Reduced keeps state changes and drops the rest.
A 20 s loop: the score climbs, headroom drains, the rollover goes pending and happens, then mail arrives on the codex row.

07 · STARTING A SESSIONThe prompt proxy becomes a short, visible plan step

  • A boxed prompt like Claude Code's, with the keys written under it. Esc starts the harness without planning at any point.
  • A spinner with elapsed time while zirv sizes the task, instead of up to 20 s of silence.
  • A plan card in plain words (model, helpers, workflow, why) with numbered choices. Every plan waits for Enter.
  • If Typesafe fails or times out, you are told, and the local-rules plan is labelled as such.
  • It runs in an inline region of the normal terminal, so it survives the harness's full-screen start (#701). One summary line is left in scrollback.
  • No seat tiers, decider names, domain scores or confidence floats on screen. zirv ctx proxy --json still has them.
