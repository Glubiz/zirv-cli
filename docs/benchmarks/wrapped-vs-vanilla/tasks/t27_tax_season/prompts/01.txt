Add a new module `ledgerlite/rulebook.py` for user rules, stored in the
ledger JSON file under a top-level `"rules"` key as a list of objects with
`id`, `pattern`, `category` and `priority`. CLI:

- `python -m ledgerlite rules add --pattern P --category C [--priority N]
  --store PATH` adds a rule (priority is an int, default 0) and prints
  `Added rule ID: P -> C (priority N)`. Rule ids are 1, 2, 3... (one more
  than the highest existing id). An empty or whitespace-only pattern is an
  error: print `error: pattern must not be empty` to stderr and exit 2.
- `python -m ledgerlite rules list --store PATH` prints one line per rule in
  id order, formatted `ID: P -> C (priority N)`, or `No rules.` when there
  are none (also when the store file doesn't exist yet).

Matching: a rule matches a transaction when its pattern appears,
case-insensitively, anywhere in the payee or the memo. When several user
rules match one transaction, the winner is the one with the highest
priority; if priorities tie, the rule with the LONGER pattern wins (more
specific); if that also ties, the lower id wins. User rules always beat the
built-in `DEFAULT_RULES`, whatever their priorities -- the built-ins are only
consulted when no user rule matches.
